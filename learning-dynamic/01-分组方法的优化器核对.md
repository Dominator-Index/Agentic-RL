# GiGPO、HGPO、GraphGPO 与 Dr. MAS 的优化器核对

核对日期：2026-10-06。结论：**本地官方代码中，GiGPO、HGPO、GraphGPO 的默认 FSDP actor 训练路径都使用 `torch.optim.AdamW`；Dr. MAS 的 FSDP actor 实现也使用 AdamW。** 这说明这些实现的优势估计改进建立在 AdamW 更新之上，不代表算法定义必须绑定 AdamW。

- `verl-agent`：`/usr/data/verl-agent`，commit `20bd331bdbc9026a5668e11362178e10ab7400c8`。
- 重点核对全参数训练脚本、Hydra 配置继承、worker 选择和优化器构造，未实际启动训练。
- PDF 的实验配置明确给出 actor 学习率；优化器类别的直接证据来自代码。没有把论文提到的 PPO critic 学习率算到这些无 critic 方法的 actor 上。

- [公共配置：strategy 与 optim](/usr/data/verl-agent/verl/trainer/config/ppo_trainer.yaml:44)。

其训练入口的 FSDP 分支都导入公共 `verl.workers.fsdp_workers`：

- [HGPO worker 选择](/usr/data/verl-agent/recipe/hgpo/main_hgpo.py:91)。
- [GraphGPO worker 选择](/usr/data/verl-agent/recipe/GraphGPO/main_graphgpo.py:91)。

最终调用 [公共优化器构造](/usr/data/verl-agent/verl/workers/fsdp_workers.py:364)：

```python
actor_optimizer = optim.AdamW(
    actor_module_fsdp.parameters(),
    lr=optim_config.lr,
    betas=optim_config.get("betas", (0.9, 0.999)),
    weight_decay=optim_config.get("weight_decay", 1e-2),
)
```

所查配置没有另行覆盖 `betas`，因此使用 `(0.9, 0.999)`；公共配置明确设置 `weight_decay: 0.01`。这些是本次所查配置的值，修改脚本、配置或切换后端后需要重新核对。

## 4. 对优化器研究的含义

GiGPO、HGPO、GraphGPO 改变优势估计或信用分配，得到新的训练梯度；AdamW 再根据梯度、历史动量和二阶矩产生参数更新。这两个层次可以联合研究。

因此，“同样使用 AdamW”不等于学习动力学相同。优势分组会改变梯度方向、尺度及其时间相关性，继而改变 AdamW 的历史统计和实际更新。

目前已有直接相关工作 [When Does Muon Help Agentic Reinforcement Learning?](https://arxiv.org/abs/2607.16169v4)，它比较不同 group-based objective 下的 Muon 与 AdamW。后续实验需要同时控制学习率、实际更新尺度和 rollout 预算，不能仅凭替换优化器后的成功率变化判断更新方向更优。
