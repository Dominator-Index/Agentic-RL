# 02. ECHO 的摘要、引言与 GiGPO setup 对比

依据：[ECHO.pdf](./ECHO.pdf)，arXiv:2606.31650v5，摘要、§1 Introduction、§3 Setup、§4 Method。整理日期：2026-10-07。

**核心结论：ECHO 仍然是同一道题采样 N 条完整交互轨迹、每条获得稀疏最终奖励。它重点改变上下文管理和正向信用的接收位置，不是像 GiGPO 那样按相同状态重新分组计算步骤优势。**

## 1. Abstract：这篇文章想解决什么

长程 agent 不断搜索、读取页面和调用工具，完整交互历史逐渐超过模型的上下文预算。删除历史或把历史折叠成摘要，可以让 agent 继续行动，却可能丢失信息的来源：最终答案用到的某个事实，究竟来自哪一轮搜索？

论文把这个问题称为来源追溯上的缺口。其动机同时涉及两个需求：

- 行动时：模型需要在有限上下文内看到有用的历史证据。
- 训练时：最终答案成功后，学习器需要知道哪些历史动作和证据应该获得信用。

ECHO 为每轮交互生成紧凑记忆，并保留来源轮次编号。上下文不足时，策略选择记忆、重建上下文；训练时复用这些来源编号，筛选获得正向信用的生成 token。

摘要报告 BrowseComp-Plus 上 ECHO 为 43.4%，GRPO 为 28.9%，滚动摘要基线 SUPO 为 36.1%；同时 ECHO 相比 SUPO 使用更少轮次和更低轨迹片段量。这里的收益来自记忆管理与信用处理的整体方案，不能把全部提升归因于单独的掩码。

## 2. Introduction：动机如何逐步展开

### 2.1 长程交互同时带来上下文与信用分配问题

最终奖励只告诉模型整个任务是否完成，但一次长程交互可能包含关键证据获取、必要准备、重复搜索、错误尝试和无用推理。共享轨迹优势无法直接区分这些部分。

与此同时，模型不能无限读取全部历史。因此，训练所面对的不只是长轨迹，还包括经过上下文管理器变换后的历史。

### 2.2 历史压缩能帮助行动，但未必帮助训练

论文讨论删除、显式记忆编辑、摘要折叠等方法。重点不只是“压缩后模型能否继续行动”，还包括“压缩后的内容能否追溯到原始环境轮次”。

例如，假设第 2 轮找到了关键日期，第 5 轮找到了人物关系，第 8 轮重复搜索且没有帮助。最终模型答对了。如果整段历史被折叠为不带来源的摘要，又把正优势赋给整条轨迹，就可能把第 8 轮也一起强化。

这是用于理解动机的示例，不是论文逐条验证的因果实验。保留来源有助于构建可操作的信用规则，但不会自动证明哪些动作真正必要。

### 2.3 ECHO 的设计：同一份来源记录同时用于行动和学习

它将两件事连接起来：

1. 从历史轮次中生成带来源编号的记忆。
2. 选择记忆以构造接下来使用的上下文。
3. 最终获得奖励后，通过来源编号决定哪些历史 token 接收正向信用。

因此，记忆选择不仅决定“模型看什么”，还提供“训练哪些生成片段”的线索。这是论文的主要侧重点。

## 3. 基础 setup：仍然是同题 N 条完整轨迹

论文 §3.1 定义，策略在第 $t$ 轮基于实际上下文 $c_t$ 生成动作：

$$
a_t\sim\pi_\theta(\cdot\mid c_t).
$$

动作可包含推理、工具调用、上下文管理或最终回答；调用工具后获得观察 $o_t$。完整轨迹为：

$$
\tau=(a_1,o_1,\ldots,a_T,o_T).
$$

对同一个任务 $x$，采样 $N$ 条完整轨迹：

$$
\mathcal G_x=\{\tau^{(1)},\ldots,\tau^{(N)}\},\qquad
R_n=R(\tau^{(n)}).
$$

这些是多次任务尝试，不是 N 个有不同分工的协作角色。实验每题使用 8 个 rollout。

与 GRPO 一样，先由最终奖励计算轨迹优势：

$$
A_n=\frac{R_n-\overline R}{\operatorname{std}(R_1,\ldots,R_N)+\epsilon}.
$$

$\overline R$ 为同题组平均奖励。ECHO 没有在这里引入 ProCredit 那样的中间验收进度，也没有在这里按锚点状态建立新的奖励归一化组。

## 4. 它新增的是上下文重建，不是新的 rollout group

论文把完整历史与模型实际看到的上下文区分开。对于某个片段 $j$：

$$
z_j=\mathcal M(H_j^{\mathrm{pre}}),\qquad
c_{j,t}=x\oplus\Phi(z_j,H_{j,t}^{\mathrm{loc}};B).
$$

$H_j^{\mathrm{pre}}$ 是此前已完成的历史；$\mathcal M$ 将它变成受管理的记忆状态 $z_j$；$H_{j,t}^{\mathrm{loc}}$ 是当前片段内近期历史；$\Phi$ 重建长度不超过预算 $B$ 的策略上下文。这里的 $\Phi$ 是上下文重建函数，不是 ProCredit 的 progress。

ECHO 的 $z_j$ 是带来源索引的记忆记录集合。策略输出选择编号，系统修复无效编号、去重并限制数量，再合并自动保留的最近轮次。

实验工作上下文为 32k token，自动保留最近 3 轮，额外选择最多 8 个历史轮次，最多允许 5 次重建。

**一条完整 rollout 可以因此保存成多个片段。这些片段仍属于同一条轨迹，并共享它的最终奖励，不是新增的独立采样轨迹，也不是 GiGPO 的同状态小组。** 论文 §3.2 明确说明片段索引是 bookkeeping。

## 5. 真正的信用改动：正优势截断 + 来源 token 掩码

令 $I_{\mathrm{src}}^{(n)}$ 表示第 $n$ 条轨迹最终重建上下文所选中的来源轮次。对保存片段 $j$ 中的生成 token $q$，构造二值掩码 $\mu_{n,j,q}$。

满足以下任一条件时，掩码为 1：

- 位于最后一次上下文重建之后的最终保存片段中；
- 属于选中来源轮次的动作 token；
- 属于这些选中来源轮次的 memory-finding token；
- 属于记忆选择操作的生成 span。

最终片段包含该片段内的推理、工具调用和最终答复，不只是最后答案；工具返回的观察本身不是策略生成的训练目标。

论文式 (16) 定义：

$$
A_n^+=\max(A_n,0),\qquad
\boxed{\widetilde A_{n,j,q}=\mu_{n,j,q}A_n^+}.
$$

它有两个独立作用：把非正优势变成零；把正优势只传给掩码选中的生成 token。

因此同一条正优势轨迹中，符合掩码的 token 得到相同的优势数值，其余为零。**这不是给每个步骤估计一个独立连续价值，而是选择哪些 token 接收原有正优势。**

也不能描述成“失败轨迹被同样掩码施加负优势”：按这条公式，负优势先被截断为零。全成功组如果组相对优势为零，也不会因为成功自动产生正向信号。

## 6. 一个与 GiGPO 对照的直观例子

假设同一问题采样了 8 条轨迹，其中一条成功轨迹最终使用了来源第 2 轮和第 5 轮的记忆。

GiGPO 会问：这批轨迹中是否出现相同锚点状态？在这些状态下产生的动作，其回报相对同组其他样本怎样？它借助锚点组重新计算步骤相对优势。

ECHO 会问：最终上下文选择了哪些历史来源？在正优势轨迹中，来源第 2 轮、第 5 轮对应的动作、finding，加上最终片段与记忆选择 token，应接收哪些正向训练信号？它无需等待另一条轨迹出现同样的状态。

## 7. 与 GiGPO、ProCredit 的区别

| 维度 | GiGPO | ProCredit | ECHO |
| --- | --- | --- | --- |
| 同题 N 条轨迹 | 是 | 是 | 是 |
| 最终奖励 | 使用 | 使用 | 使用 |
| 额外中间验收进度 | 不要求 | 要求可执行检查 | 不要求这种进度信号 |
| 主要信用依据 | 同锚点样本的回报比较 | 进度差分与后续累计回报 | 最终上下文重建的来源记录 |
| 步骤组 | 按锚点再分组 | 同题全部轮次公共参考 | 不建立同状态步骤组 |
| 上下文管理 | 不是主要贡献 | 不是主要贡献 | 核心组成 |
| 对训练信号的主要改动 | 计算步骤相对优势 | 计算轨迹和轮次优势 | 正优势截断与 token 掩码 |

ProCredit 论文中的 GiGPO 对照额外使用了相同 progress rewards；不能把表中原始方法的反馈要求误当成那个对照实验的配置。

## 8. ECHO 能证明什么，尚不能证明什么

- 它保留可用的来源指针，因而能构造确定的信用掩码。
- “最终选择了某条记忆”不等于该记忆因果上必不可少，也不保证它的全部原始动作 token 都有效。
- 它使用 final-trace 近似，不递归追踪所有中间记忆重建依赖，因此可能漏掉间接有用的早期动作。
- 性能收益可能同时来自更好的上下文选择、正优势截断和来源掩码；应通过消融区分，不能把全部提升归为来源信用。
- 它没有解决细粒度优势估计的全部问题，而是为压缩历史后的正向信用筛选提供了可执行机制。

## 9. 阅读时要注意代码版本

本地归档的作者仓库 commit 为 `41b0e42ee06c6ec2fd62e594bf59aee91f1576dd`。其 README 已以 ECHO-Graph 为主，同时列出 ECHO-v1 token-credit 模式与 graph 模式。

**本文讲解的是 PDF v5 的 final-trace token mask。不要把仓库后续 graph-credit 模式直接当成本文式 (15)–(17) 的实现。** 仓库区分了 `ECHO_CREDIT_METHOD=token` 与 `ECHO_CREDIT_METHOD=graph`；复现前需核对入口、配置及对应版本，而不是只运行默认脚本。

## 10. 核心定位

ECHO 的基础采样仍然沿用同题多轨迹、稀疏结果奖励的训练框架。它的特色是把“历史怎么压缩、哪些记忆被选中”和“哪些生成 token 应获得正向信用”连接起来。GiGPO 主要研究同状态下怎样进行局部回报比较，ECHO 主要研究有限上下文下怎样保留并利用证据来源。
