## 1. 它解决什么问题

长程 agent 需要压缩历史，才能在有限上下文中继续搜索和调用工具。但把许多历史轮次折叠为一段摘要后，训练阶段很难追溯：最终成功使用了哪几轮早期证据？

ECHO 将记忆管理与信用分配连接起来：压缩后的记忆保留来源轮次编号；后续选择哪些记忆既决定模型看什么，也决定哪些历史生成 token 获得正向训练信用。

## 2. 方法流程

1. 每个已完成的环境交互轮次产生带来源编号的紧凑记忆，包含动作信息与生成的 finding。
2. 到达上下文压缩边界时，由同一策略生成需要保留的历史来源编号。
3. 对编号进行合法性修复、去重和数量限制，再合并自动保留的最近轮次，重建受预算约束的上下文。
4. 回合结束后，根据最终重建上下文选中的来源，构造生成 token 的信用掩码。
5. 用掩码选择性地传递正的组相对优势。

具体实验每题采样 8 个 rollout，工作上下文为 32k；保留最近 3 轮，并最多选择 8 个额外历史轮次，最多重建 5 次。各策略调用受 32k 限制，允许的总交互量可到 192k。来源索引档案与每次送给模型的紧凑上下文是不同对象。

## 3. 最值得记住的公式

论文保留组相对的轨迹优势 $A^{(n)}$，但不把它均匀赋给所有 token。对于第 $n$ 条轨迹、保存片段 $j$、生成 token $q$，定义掩码 $\mu_{j,q}^{(n)}$，满足以下任一条件时为 1：

- token 在最终保存的轨迹片段中；
- token 属于最终选中来源轮次的动作；
- token 是这些选中来源轮次的 memory finding；
- token 属于记忆选择 span。

这里的“最终片段”包含最后一次重建之后的推理、工具调用及最终答复，不只是最后答案。

论文式 (16)：

$$
A_+^{(n)}=\max(A^{(n)},0),\qquad
\widetilde A_{j,q}^{(n)}=\mu_{j,q}^{(n)}A_+^{(n)}.
$$

因此，变化主要发生在**信用的正值截断和 token 掩码**，不是引入新的中间奖励或重新按相同状态计算均值、标准差。只有正优势轨迹会通过这一项获得非零信用；二值奖励下全成功组若优势为零，也不会因“成功”自动得到正梯度。

论文式 (17) 以简化的策略梯度 surrogate 表达：

$$
J_{\mathrm{ECHO}}^{(n)}(\theta)
=\sum_j\sum_q\widetilde A_{j,q}^{(n)}
\log\pi_\theta(y_{j,q}^{(n)}\mid c_j^{(n)},y_{j,<q}^{(n)}).
$$

$y$ 是生成 token，$c$ 是当时使用的上下文。这是论文的简化数学表达，具体训练中的 clipping、归一化等细节应进一步对照配置和源码。

## 4. 与我们已有论文的差别

| 方法 | 关键机制 |
| --- | --- |
| GiGPO / HGPO | 按状态或历史构造可比较的组，计算细粒度相对优势 |
| GraphGPO | 由跨轨迹状态图构造信用信号 |
| ProCredit | 重跑环境验收检查，利用进度变化和后续回报构造轮次优势 |
| ECHO | 保留记忆来源，用最终选择记录决定正向信用传给哪些 token |

ECHO 与 history 有关，但它选择的是上下文中值得保留的历史证据，并利用选择记录分配信用，未建立 GiGPO 式同状态跨轨迹分组。

## 5. 结果与边界

论文报告 BrowseComp-Plus 上 ECHO 为 43.4%，GRPO 为 28.9%，SUPO 为 36.1%；ECHO 相比 SUPO 使用更少的交互轮次和轨迹片段。记忆选择与信用掩码的消融支持二者的实用价值。它还报告了多任务零样本迁移结果，详见正文 §5。

解释时需要注意：

- **最终选中不等于因果上必要。** 来源追踪提供可计算的相关性线索，没有逐个删除证据验证反事实贡献。
- 采用 final-trace 近似，只追踪最终上下文的来源，没有递归追踪所有中间选择依赖；间接有用的早期轮次可能遗漏。
- 正优势截断与来源掩码共同改变训练信号；比较中需要区分“去掉负优势”和“按来源选择 token”各自的作用。
- 本文有上下文扩展和记忆选择带来的作用，不能把全部最终性能提升都归因于信用分配。
- arXiv 元信息列出 10 位作者，本地 v5 PDF 首页另列 Xiaoliang Fu；若整理正式引用，应核对采用的版本。
