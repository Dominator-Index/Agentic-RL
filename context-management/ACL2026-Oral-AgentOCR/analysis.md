# AgentOCR：把交互历史变成可压缩视觉记忆

## 1. 核心问题与贡献

Agent 的交互历史不断增长，完整文本历史增加上下文开销，直接截断又会丢失任务信息。AgentOCR 把历史文字渲染成图片，让视觉语言模型读图，并学习选择压缩强度。它修改的是**历史的表示及其成本**，不是 GRPO 的比较组或 advantage 粒度。

来源：[论文](https://arxiv.org/abs/2601.04786)、[本地 PDF](./AgentOCR.pdf)、[代码](./AgentOCR)。以下结合论文方法部分、附录及公开实现说明。

## 2. 数据流与数学形式

设历史为 $h_t=(o_1,a_1,\ldots,o_t)$，文本渲染为 $I_t=\operatorname{Render}(h_t)$。策略读取任务、当前输入和视觉历史，联合输出环境动作与压缩决定：

$$
(a_t,c_t)\sim\pi_\theta(\cdot\mid x,o_t,I_t).
$$

这里是同一策略输出动作与类似 `<compression>c</compression>` 的标记，而不是另训一个独立 compressor policy。压缩决定作用于后续历史图像。若原图尺寸是 $H\times W$，按面积压缩因子 $c$ 缩放为：

$$
H'=H/\sqrt c,\qquad W'=W/\sqrt c.
$$

像素面积约变成 $1/c$；实际视觉 token 数还受处理器的尺寸取整、patch 和上下限影响，不能把它当成严格的 token 数公式。

历史按片段缓存：重复片段复用已渲染图片，再按历史顺序组合。缓存减少文字渲染工作，不代表历史长度停止增长，也不是 Transformer KV cache 的同义词。实现为每个环境维护 episode 内缓存，在 episode 边界重置。

## 3. 奖励为何能学到压缩

论文以任务成功门控压缩奖励，核心形式为：

$$
\widetilde r_t=r_t+\lambda\,\mathbf1\{\text{success}\}\log c_t.
$$

成功时较高压缩有额外收益；失败时不能只靠压缩获得这部分成功奖励。论文使用小系数及间隔施加压缩奖励的训练方式，防止模型过早一味压缩。其训练仍可使用 GRPO，压缩收益通过同一策略梯度影响动作与压缩选择。

实现不能简单理解为“把环境每步即时奖励加上这一项”：`agent_system/reward_manager/episode_with_compression.py` 读取 episode reward、成功标记及当前压缩因子，按配置进行间隔门控，支持按 episode 长度归一化，并把对应分数放到响应末 token。应结合实际配置理解训练信号。

与本目录分组主线的区别是：AgentOCR 改变 $X$ 的表示及 $Y$ 的奖励组成，而 GiGPO/HGPO 主要改变哪些样本互相比较。二者原则上可组合，但视觉压缩可能引起状态混淆，需要重新验证分组键的可靠性。

## 4. 实验证据与限制

论文 7B 设置中，ALFWorld 的文本基线成功率 81.8、AgentOCR 81.2，上下文 token 指标由约 0.95k 降至 0.43k；QA 对应分数 41.9 与 40.1，token 约 0.73k 与 0.36k。不能据此宣称每个设置都保留至少 95% 性能，或直接把 token 降幅当成端到端延迟降幅。文本与视觉语言模型骨干也并非完全相同的权重。

缓存消融中，所报渲染耗时约从无缓存的 3509 ms 降至 168.77 ms；相对约 203 ms 的朴素缓存，额外收益要小得多。主要证据支持压缩与渲染开销改善，没有给出对任意任务的性能保持定理。

精确数字、长文本检索和细小字符可能更容易受压缩损伤；图像历史仍持续增长。模型学到的是任务相关的压缩折中，并没有解决无限记忆问题。

## 5. 代码核对入口与可复用认识

- `agentocr/ocrtool.py`：`SegmentCache`、片段划分、历史渲染与缓存。
- `agent_system/reward_manager/episode_with_compression.py`：成功门控、压缩奖励、间隔和长度归一化。

最值得借鉴的思想是：**把上下文成本转化成策略能选择、奖励能约束的变量**。它属于表示与预算优化，不属于跨 trajectory 的 step advantage 重组。
