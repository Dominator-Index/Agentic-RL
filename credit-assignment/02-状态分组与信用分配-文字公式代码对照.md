| 数学／文字含义 | 代码字段 |

## 2. GiGPO：同题 → 相同观察 → 组内比较实际回报

### 2.1 当前观察与完整 prompt 是两个字段

[环境管理器](/usr/data/verl-agent/agent_system/environments/env_manager.py:147) 的关键语句：

```python
full_text_obs = self.build_text_obs(text_obs, self.envs.get_admissible_commands, init=True)
return {'text': full_text_obs, 'image': image_obs, 'anchor': text_obs}, infos
```

`full_text_obs` 是给模型的输入文本；`text_obs` 是用于锚点匹配的当前观察。rollout 将后者保存为 `anchor_obs`。这解释了为什么两个分组样本可能有相同 state key，却有不同历史 prompt。

### 2.2 一行代码对应一个状态组

公式是：

$$
\mathcal G_x(s)=\{(i,t):s_t^{(i)}=s\}.
$$

[build_step_group](/usr/data/verl-agent/gigpo/core_gigpo.py:277) 的精确匹配分支，省略生成 group UUID 的后半段：

```python
for idx in unique_indices:
    if not enable_similarity:
        indices = np.where(index == idx)[0]
        obs_group = anchor_obs[indices]
        clusters = defaultdict(list)
        for i, obs in enumerate(obs_group):
            clusters[to_hashable(obs)].append(indices[i])
```

逐行含义：先取同一任务的步骤行，再把观察转成字典 key，最后将 key 一样的行号收在一起。对字符串，`to_hashable` 直接返回该字符串；它不是语义编码器。数组会被转换成可哈希的表示。

**这里既没有要求 `traj_index` 不同，也没有要求 action 文本不同。** 一条轨迹内的重访可以进入同组，重复动作仍然保留为不同的数据行。分组依据也不是“大家都在第 t 步”。

相似度选项属于另一分支。论文搜索 QA 实验报告阈值 0.9；不能因此将 ALFWorld 基本实现也描述为语义状态聚类。[GiGPO §5.1](./NeurIPS2025-GiGPO/GiGPO.pdf)

### 2.3 后续回报和局部优势

$$
G_t^{(i)}=r_t^{(i)}+\gamma G_{t+1}^{(i)},\qquad
A_{i,t}^{S}=\frac{G_t^{(i)}-\mu_{\mathcal G_x(s_t^{(i)})}}
{\sigma_{\mathcal G_x(s_t^{(i)})}+\varepsilon}.
$$

第一式把该轨迹实际得到的未来奖励反向累积；第二式在相同观察组内比较这些回报。$\mu$、$\sigma$ 是该组统计量。`mean_norm` 模式只做减均值。

[回报计算](/usr/data/verl-agent/gigpo/core_gigpo.py:116) 原始片段：

```python
for t in reversed(range(len(traj_rewards))):
    running_return = traj_rewards[t] + gamma * running_return
    traj_returns[t] = running_return
```

[step_norm_reward](/usr/data/verl-agent/gigpo/core_gigpo.py:378) 中对应的归一化与 token 广播：

```python
for i in range(bsz):
    if remove_std:
        scores[i] = scores[i] - id2mean[index[i]]
    else:
        scores[i] = (scores[i] - id2mean[index[i]]) / (id2std[index[i]] + epsilon)
step_advantages = scores.unsqueeze(-1).tile([1, response_length]) * response_mask
```

这里 `index` 已经是步骤组 ID。一个步骤得到一个标量优势，随后复制给该步骤的有效 response token；**这不是在同一步内部为每个 token 单独估计贡献**。

### 2.4 总优势仍包含整轨迹项

$$
A_{i,t}^{\mathrm{GiGPO}}=A_i^E+\omega A_{i,t}^S.
$$

[主函数](/usr/data/verl-agent/gigpo/core_gigpo.py:160) 调用链：

```python
episode_advantages = episode_norm_reward(token_level_rewards, response_mask, index, traj_index, epsilon, remove_std)
step_group_uids = build_step_group(anchor_obs, index, enable_similarity, similarity_thresh)
step_advantages = step_norm_reward(step_rewards, response_mask, step_group_uids, epsilon, remove_std)
scores = episode_advantages + step_advantage_w * step_advantages
```

`step_advantage_w` 对应 $\omega$。因此某步没有重复锚点、局部优势为零时，整轨迹项仍可能提供更新。单例组的均值就是自身分数，代码将其标准差设为 1，中心化后为零。

## 3. HGPO：当前观察相同，再按历史观察后缀分层

### 3.1 公式中的 k 与代码中的 k 不是同一计数方式

论文中 $k$ 表示**历史观察个数**：

$$
C_k(i,t)=(s_{\max(1,t-k)}^{(i)},\ldots,s_t^{(i)}),\qquad
\mathcal G_k(i,t)=\{(j,u):C_k(j,u)=C_k(i,t)\}.
$$

例如 $C_0=(U)$，$C_1=(A,U)$，$C_2=(S,A,U)$。每个样本同时属于多个层，而不是只挑一个最细的组。

[实际分组循环](/usr/data/verl-agent/recipe/hgpo/core_hgpo.py:243)：

```python
for ti in range(n_traj):
    T = len(traj_h[ti])
    for si in range(T):
        k_upper = min(max_k, si + 1)
        for k in range(1, k_upper + 1):
            seq = traj_h[ti][si - k + 1 : si + 1]
            clusters[(k, tuple(seq))].append((ti, si))
```

这里代码 `k` 是**包含当前观察的后缀总长度**，从 1 开始。代码 `k=1` 对应论文 $k=0$；代码 `k=2` 对应论文 $k=1$。`traj_h` 来自 `anchor_obs`，所以匹配的是观察序列，不是完整的历史动作和推理文本。

### 3.2 每层先独立算优势

$$
A_{i,t}^{(k)}=\frac{G_t^{(i)}-\mu_{\mathcal G_k(i,t)}}
{\sigma_{\mathcal G_k(i,t)}+\varepsilon}.
$$

各层使用同一个实际后续回报，区别在于跟谁比较。[原始代码](/usr/data/verl-agent/recipe/hgpo/core_hgpo.py:253)：

```python
for (k, _key), members in clusters.items():
    nL = len(members)
    if nL <= 1:
        continue

    r = torch.stack([traj_rewards[ti][si] for (ti, si) in members], dim=0)
    mean = r.mean()
    std = r.std(unbiased=False)

    if mode == "mean_std_norm":
        a = (r - mean) / (std + epsilon)
    elif mode == "mean_norm":
        a = (r - mean)
```

这里的 `traj_rewards` 保存步骤回报，单例层直接跳过。较长历史没有重复，不妨碍较短历史层继续提供比较。

### 3.3 聚合权重：论文与当前实现应分别阅读

论文 Eq. (7)：

$$
w_k=\frac{(k+1)^\alpha}{\sum_{j=0}^K(j+1)^\alpha},\qquad
A_{i,t}^H=\sum_{k=0}^K w_k A_{i,t}^{(k)}.
$$

$\alpha$ 控制偏向长历史的程度。当前 [aggregate_items](/usr/data/verl-agent/recipe/hgpo/core_hgpo.py:196) 原始片段：

```python
valid_mask = (advs != 0)
if valid_mask.any():
    advs_v = advs[valid_mask]
    ks_v = ks_t[valid_mask]
    L = ks_v + 1
    w_raw = L ** length_weight_alpha
    w = w_raw / (w_raw.sum() + epsilon)
    items_val = (w * advs_v).sum()
```

有两处实际差别：

1. 代码只对该样本的非零层优势重新归一化权重；论文展示的是全部层上的公式。
2. 分组循环传进来的 `k` 已是后缀总长度，聚合时又计算 `L=k+1`。在默认不加轨迹组的情况下，当前观察层的原始权重是 $2^\alpha$，下一层是 $3^\alpha$；而论文对应的是 $1^\alpha$、$2^\alpha$。这是当前 commit 的编号／权重差异，不能把代码称作 Eq. (7) 的逐字实现。

默认参数 [base_group=False](/usr/data/verl-agent/recipe/hgpo/core_hgpo.py:157) 表示不额外加入轨迹优势。当所有层都没有有效相对信号时，该步 HGPO 优势可以为零。

## 4. GraphGPO：同状态建图，图评分再按同起点比较

### 4.1 节点是 state，边保留 action 和出现实例

$$
\mathcal V_x=\{\text{同任务已观察到的匹配状态}\},\qquad
\mathcal E_x=\{(s_t^{(i)},a_t^{(i)},s_{t+1}^{(i)})\}_{i,t}.
$$

不同轨迹出现的同状态合并为节点；重复转移仍以边实例保留。[from_data](/usr/data/verl-agent/recipe/GraphGPO/core_graph.py:150) 内层原始片段：

```python
anchor_h = canon.canonicalize(data.non_tensor_batch['anchor_obs'][i])
next_h   = canon.canonicalize(data.non_tensor_batch['next_obs'][i])
g.add_edge(
    anchor_h,
    next_h,
    action=data.non_tensor_batch['text_actions'][i],
    traj_uid=data.non_tensor_batch['traj_uid'][i],
    uid=data.non_tensor_batch['uid'][i],
    data_id=i,
    episode_rewards=data.non_tensor_batch['episode_rewards'][i],
    weight=weight
)
```

外层先按任务 `uid` 建图，主实现 `weight=1.0`。边中的 `action` 保存生成文本相关数据；它不是用于合并节点的 key。因此，“GraphGPO 只合并相同 state-action pair”不准确。

### 4.2 图距离不是该条轨迹自己的实际后续长度

$$
d(g)=0,\qquad d(s)=\min_{(s,a,s')\in\mathcal E_x}\{c(s,a)+d(s')\}.
$$

$g$ 是成功节点，$c$ 是边成本。这是已采样经验图上到成功的最短成本，可以借用其他轨迹提供的边；不是对真实环境最优距离的保证。

[all_to_target_shortest_paths](/usr/data/verl-agent/recipe/GraphGPO/core_graph.py:285) 的两段关键代码：

```python
reverse_graph[v].append((u, w))
```

```python
for neighbor, w in reverse_graph[node]:
    new_cost = cost + w
    if new_cost < distances[neighbor]:
        distances[neighbor] = new_cost
        paths[neighbor] = [neighbor] + path
        heapq.heappush(pq, (new_cost, neighbor, [neighbor] + path))
```

先反向存边，再从成功节点运行 Dijkstra。不可达节点随后被设为最大有限距离加 1，记为 $\bar d(s)$。

### 4.3 先生成图分数，再使用 GiGPO 的分组函数

论文主评分为：

$$
R^G(s,a,s')=r_{\mathrm{succ}}\omega^{\bar d(s')+c(s,a)}.
$$

$0<\omega<1$，因此通过当前边后剩余成功成本越低，分数越高。对同一个起点的出边实例建立 $\mathcal G_x(s)$，中心化或标准化这些图分数。

当前 [compute_graph_path_returns](/usr/data/verl-agent/recipe/GraphGPO/core_graph.py:822) 的代码是：

```python
if normalize_distance:
    traj_returns[t] = 10*gamma**(distances_dict[new_h]-distances_dict[old_h]+weight)
else:
    traj_returns[t] = 10*gamma**(distances_dict[new_h]+weight-1)
```

默认非距离归一化分支相对论文有奖励尺度及指数减一的区别。令 $r_{\mathrm{succ}}=10$、$\omega=\gamma$，两者相差共同正因子 $1/\gamma$；除组标准差时该尺度基本抵消，只减均值时仍影响优势大小。另一个分支是实现选项，不能混写为论文主公式。

[compute_graphgpo_outcome_advantage](/usr/data/verl-agent/recipe/GraphGPO/core_graph.py:888) 直接复用：

```python
step_group_uids = build_step_group(anchor_obs, index)
step_advantages = step_norm_reward(step_rewards, response_mask, step_group_uids, epsilon, remove_std)
```

这里 `step_rewards` 已替换成图分数。**分组仍然按同起点观察；主要变化在评分来源。** 后续按权重加入 episode advantage。构图可以配置相似匹配，但此处调用未传相似度参数，按函数默认值进行精确匹配，不能假设所有阶段共用同一个相似聚类结果。

## 5. ProGPO：比较组来自基础方法，progress 另行计算

### 5.1 论文：在每条轨迹自己的 visited set 中判断首次访问

$$
\mathcal V_{i,t}=\{o_1^{(i)},\ldots,o_t^{(i)}\},\quad
\delta_{i,t}=\mathbf1\{o_{t+1}^{(i)}\notin\mathcal V_{i,t}\},\quad
P_i=\frac1{T_i}\sum_t\delta_{i,t}.
$$

这是轨迹自己的新观察覆盖比例，不需要寻找其他轨迹的相同中间状态。对应论文定义的**解释性伪代码，不是当前仓库原文**：

```python
visited = {observations[0]}
progress = []
for next_observation in observations[1:]:
    progress.append(float(next_observation not in visited))
    visited.add(next_observation)
P = sum(progress) / len(progress)
```

论文 Eq. (7) 的轨迹级条件优势：

$$
A_i=\begin{cases}
\dfrac{R_i-\overline R}{\sigma_R+\varepsilon},&\sigma_R\ge\tau_R,\\
\lambda\dfrac{P_i-\overline P}{\sigma_P+\varepsilon},&\sigma_R<\tau_R,\ \overline R=0,\ \sigma_P\ge\tau_P,\\
0,&\text{其他情况}.
\end{cases}
$$

$R_i$ 是任务结果，$P_i$ 是观察覆盖，阈值用于判断是否有足够差异，$\lambda$ 控制替代优势尺度。正常回报有差异时用回报；全失败且 progress 有差异时才用替代信号。论文二元奖励设定中，全成功不触发这个修复。

### 5.2 当前代码 C2 与首次访问定义不同

[rollout_loop.py](/usr/data/ProGPO/agent_system/multi_turn_rollout/rollout_loop.py:499) 摘取关键语句，省略中间注释：

```python
obs_changed = str(cur_anchor_i) != str(next_anchor_i)
reward_delta_positive = float(rewards_np[i]) > 0
if progress_mode == 'C2':
    progress_val = float(obs_changed)
    if reward_delta_positive:
        progress_val = max(progress_val, 1.0)
```

代码自己的注释也明确指出，重访以前的状态，只要当前转移改变观察，仍然计分。该分支并未查询整条轨迹的 visited set。

| 观察序列 | 论文首次访问标记 | 当前 C2 的变化标记，假设奖励全零 |
|---|---|---|
| `A → B → A` | `1, 0` | `1, 1` |
| `A → A → B` | `0, 1` | `0, 1` |

所以不能拿当前 C2 的观测变化直接解释为论文的首次访问覆盖；这也是把公式和代码放在一起阅读的必要性。这里只记录差异，没有修改作者实现。

### 5.3 接 GRPO：可以在任务级比较 progress

[GRPO 优势函数](/usr/data/ProGPO/verl/trainer/ppo/core_algos.py:286) 在 `not steplevel_active` 分支按 `traj_index` 将 `step_progress` 求平均，形成 `traj_progress`，再按任务组判断和修复全失败情况。

这对应 $P_i=\operatorname{mean}_t\delta_{i,t}$ 和同题轨迹比较；**该分支不要求跨轨迹中间观察相同**。但当前实现提供额外 step-level 配置，入口是否开启它需检查 `progpo_ray_trainer.py` 的参数和分发，不能仅凭 `adv_estimator='grpo'` 推断最终行为。

### 5.4 接 GiGPO：保留同状态组，再切换组内评分

[ProGPO 仓库的 GiGPO 入口](/usr/data/ProGPO/gigpo/core_gigpo.py:183) 仍调用：

```python
step_group_uids = build_step_group(anchor_obs, index, enable_similarity, similarity_thresh)
```

在 [step_norm_reward](/usr/data/ProGPO/gigpo/core_gigpo.py:469) 内，对全失败步骤组启用下面的修复。省略索引装配和统计日志：

```python
p_mean = p.mean()
p_std = p.std(unbiased=False)
if float(p_std) >= 1e-4:
    a_repair = (p - p_mean) / (p_std + epsilon) * lambda_eff
```

对应的公式是：

$$
A_{i,t}^{\mathrm{repair}}=\lambda_{\mathrm{eff}}
\frac{p_{i,t}-\operatorname{mean}_{(j,u)\in\mathcal G_x(s_t^{(i)})}p_{j,u}}
{\operatorname{std}_{(j,u)\in\mathcal G_x(s_t^{(i)})}p_{j,u}+\varepsilon}.
$$

这里 $p_{i,t}$ 对应逐步 `step_progress`，不是整轨迹 $P_i$。代码用组内 `max(abs(return))` 小于阈值识别全零组，并将 $\lambda_{\mathrm{eff}}$ 按全失败组比例缩放；这些是实现细节，不能与论文 Eq. (7) 的全部条件视为逐字一致。

接 HGPO 时同理：保留历史组，再在相应组内替换评分，见 [ProGPO 的 HGPO 实现](/usr/data/ProGPO/recipe/hgpo/core_hgpo.py:165)。因此，ProGPO 不会自动解决“状态组只有一个样本”的问题；它主要补充“已有比较组的回报全零，但行为过程仍有差异”的信号。

## 6. 其他三篇：公式能核对，尚不能冒充官方代码讲解

### 6.1 CRBC：共享状态决定 Bellman 信息能传播到哪里

统计同状态、动作和后继的出现频率，得到 $\widehat\mu(a\mid s)$ 和 $\widehat P(s'\mid s,a)$。论文设置成功边界值为 1、失败边界值为 0，然后计算：

$$
Q(s,a)=\beta\sum_{s'}\widehat P(s'\mid s,a)V(s'),\qquad
V(s)=\sum_a\widehat\mu(a\mid s)Q(s,a).
$$

$0<\beta<1$ 为折扣。按经验行为频率求期望，和 GraphGPO 的最短成功路评分不同。最终用经过局部尺度归一化的 $Q-V$ 构造步骤信用，并结合轨迹项。

**解释性伪代码，不是作者代码：**

```python
counts[state, action, next_state] += 1
# 用 counts 构造非终止转移矩阵 M 和成功边界贡献 b
V = solve(I - beta * M, b)
Q[state, action] = beta * expected_next_value(state, action, V)
credit[state, action] = Q[state, action] - V[state]
```

`state` 合并规则决定哪些轨迹能共享后续证据。完整线性方程、尺度和至少两个语义动作的条件见 [CRBC 分析](./arXiv2026-CRBC/analysis.md)。

### 6.2 ProCredit：验证每轮进度，不匹配跨轨迹相同观察

$$
\Phi_g(s)=\frac1{K_g}\sum_{m=1}^{K_g}C_{g,m}(s),\qquad
r_{i,t}=c\bigl(\Phi_g(s_{i,t})-\Phi_g(s_{i,t-1})\bigr).
$$

$C_{g,m}$ 是任务 $g$ 的第 $m$ 个可执行检查，$\Phi_g$ 是通过比例；这里 $s_{i,t}$ 表示第 $t$ 轮动作后的环境状态。进度上升得正奖励，下降得负奖励。

逐轮项使用同任务全部 turns 的回报均值：

$$
A_{i,t}^{\mathrm{turn}}=G_{i,t}-\frac1{|U_g|}\sum_{(j,u)\in U_g}G_{j,u}.
$$

$U_g$ 不按相同 observation 拆分，因此没有跨轨迹重复状态这一前提。训练时需要访问和验证中间环境状态，是不同的监督条件。

**解释性伪代码，不是作者代码：**

```python
phi_before = evaluate_acceptance_checks(state_before)
phi_after = evaluate_acceptance_checks(state_after)
turn_reward = c * (phi_after - phi_before)
# 累积每轮 return 后，在同任务全部 turns 中减去共同均值
```

项目页仍标注代码待发布；完整优势公式见 [ProCredit 分析](./arXiv2026-ProCredit/analysis.md)。

### 6.3 SCA：共同截图由采样设置保证

固定 $x=(\text{截图},\text{指令})$，采样多个点击响应 $a_i$。这是已经给定的共同决策情境，不是在长轨迹里搜索共享节点。

全失败分支使用到标注目标中心 $c_T$ 的距离构造分数：

$$
p_i=\exp\left(-\frac{\|a_i-c_T\|_2}{\ell_T}\right).
$$

$\ell_T$ 是目标尺度相关的归一化长度；再对这些分数做相对归一化并施加门控系数。混合成败分支则利用留一预测的奖励残差，不能全部概括成距离奖励。详见 [SCA 分析](./arXiv2026-SCA/analysis.md)。

本次没有确认官方代码，因此这里只将论文公式和操作对应，不给虚构文件名或代码行号。

## 7. 最后都要回到真实样本的 policy loss

令 $p_{i,t}$ 为实际 prompt、$y_{i,t,\ell}$ 为该步生成 token：

$$
\rho_{i,t,\ell}=\frac{\pi_\theta(y_{i,t,\ell}\mid p_{i,t},y_{i,t,<\ell})}
{\pi_{\theta_{\mathrm{old}}}(y_{i,t,\ell}\mid p_{i,t},y_{i,t,<\ell})}.
$$

上面的算法计算优势 $A_{i,t}$；概率比始终在该样本自己的上下文中计算。基本 clipped loss 是：

$$
L=-\operatorname{Avg}_{\text{有效 response token}}
\min\{\rho_{i,t,\ell}A_{i,t},\operatorname{clip}(\rho_{i,t,\ell},1-\epsilon,1+\epsilon)A_{i,t}\}.
$$

[compute_policy_loss](/usr/data/verl-agent/verl/trainer/ppo/core_algos.py:472) 的基本项摘录，省略可选 clipping 分支：

```python
negative_approx_kl = log_prob - old_log_prob
ratio = torch.exp(negative_approx_kl)
pg_losses1 = -advantages * ratio
pg_losses2 = -advantages * torch.clamp(ratio, 1 - cliprange_low, 1 + cliprange_high)
clip_pg_losses1 = torch.maximum(pg_losses1, pg_losses2)
```

实际函数还支持双侧不同 clip 范围、dual-clip 和不同聚合模式，上式只展示核心对应关系。**改变分组或图评分，是改变 `advantages` 的构造；不是把不同样本的策略概率拿来相除。**
