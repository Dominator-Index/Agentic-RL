# 01｜同状态分组的前提与边界：GiGPO、HGPO、GraphGPO、ProGPO 等方法

核对日期：2026-10-08。本文围绕一个问题：**这些方法是否都需要不同 trajectory 到达“相同 state”，否则就不能分组？**

方法与环境范围沿用已经核对的 [07｜逐篇论文的数据集与任务分类总表](../07-逐篇论文的数据集与任务分类总表.md)，本次进一步核对原始 PDF 和本地官方代码。逐段的文字、公式、代码对应见 [02｜状态分组与信用分配：文字、公式、代码对照](./02-状态分组与信用分配-文字公式代码对照.md)。

## 1. 结论：对 GiGPO、HGPO、GraphGPO 的局部机制成立，但不能推广到整个目录

**GiGPO、HGPO、GraphGPO，以及 CRBC，都利用可匹配的状态来共享局部比较或后续路径信息。没有重复的匹配状态，这部分跨轨迹信息利用就会明显退化。** 但它们不要求全部轨迹、全部时间步都有重复状态，也不要求组内动作文本彼此不同。

**ProGPO 必须区分接入版本。** 它用观测新颖性补充全失败组的学习信号；其轨迹级版本只需要比较同任务的轨迹，不要求跨轨迹存在共同的中间状态。接到 GiGPO／HGPO 的局部分组上时，才继承相应的状态／历史匹配条件。

| 方法 | “相同 state”用于什么 | 是否依赖跨轨迹共同的中间状态 |
|---|---|---|
| **GiGPO** | 按相同当前观察收集动作出现实例，在组内比较后续回报 | 局部优势依赖重复锚点；重复也可以发生在同一轨迹内部 |
| **HGPO** | 先按当前观察匹配，再增加最近历史观察的一致性约束 | 同样依赖重复锚点；长历史层还需要重复观察后缀 |
| **GraphGPO** | 合并同状态节点、连接已观察转移，并按同起点比较出边 | 跨轨迹连接与局部出边比较都利用共享状态 |
| **CRBC** | 合并共享锚点，统计动作／转移频率，传播 Bellman 信用 | 跨轨迹传播依赖共享锚点；不是只做组均值归一化 |
| **ProGPO：轨迹级版本** | 在每条轨迹内判断哪些观察首次出现，再比较轨迹 progress | **不要求跨轨迹中间状态重复**；同题轨迹组仍然存在 |
| **ProGPO＋GiGPO／HGPO** | 保留基础方法的步骤组，在全失败组中替换评分信号 | **继承所接基础方法的匹配条件** |
| **ProCredit** | 在每轮后的环境状态执行任务验收检查，计算进度变化 | **不要求**；逐轮信用来自进度奖励和同任务参考均值 |
| **SCA** | 对同一截图＋指令采样多个候选点击 | 起点本来就相同；**不需要从多条长轨迹中寻找重访状态** |

依据：[GiGPO §4](./NeurIPS2025-GiGPO/GiGPO.pdf)、[HGPO §4.2](./ICLR2026-HGPO/HGPO.pdf)、[GraphGPO §4](./ICML2026-GraphGPO/GraphGPO.pdf)、[CRBC §4](./arXiv2026-CRBC/CRBC.pdf)、[ProGPO §4](./arXiv2026-ProGPO/ProGPO.pdf)、[ProCredit §3](./arXiv2026-ProCredit/ProCredit.pdf)、[SCA 方法部分](./arXiv2026-SCA/SCA.pdf)。

## 2. 先分清 state、observation、prompt 和 action

以 ALFWorld 为例，任务是“找到鸡蛋，加热后放到台面上”。环境可能返回：

```text
当前观察：你来到冰箱 1 前，冰箱关着。
```

模型实际收到的输入还包含任务、近期交互历史、当前步数和允许执行的动作。模型输出则包含推理文字与动作指令，例如打开冰箱；程序解析动作后交给环境，得到下一条观察。

| 层次 | 具体含义 | 本地实现中的对应 |
|---|---|---|
| 环境完整状态 | 物体位置、持有物、容器开关、物品是否加热等全部相关条件 | 不一定全部包含在当前观察里 |
| 当前 observation | 环境这一轮返回的文本或图像 | `text_obs` 等 |
| 分组用的 state key | 用来认定哪些步骤可归到同一个锚点的表示 | `anchor_obs`；ALFWorld 基本实现取 `text_obs` |
| 模型完整输入 | 任务＋历史＋当前观察＋其他提示字段 | `full_text_obs`，随后转换为 prompt token |
| 模型生成的 response | 这一轮的推理文字和动作格式 | RL 更新使用的 response token |
| 环境执行的 action | 从 response 中解析出的指令，如 `open fridge 1` | projection 函数提取后传给 `env.step` |

因此，**观察相同不等于完整环境状态相同，也不等于模型的完整输入相同。** GiGPO 的锚点匹配首先是一种实现层面的状态表示选择，并不是对真实 Markov 状态等价性的证明。

证据：[ALFWorld 的 anchor 和完整输入分别构造](/usr/data/verl-agent/agent_system/environments/env_manager.py:148)、[动作解析](/usr/data/verl-agent/agent_system/environments/env_package/alfworld/projection.py:43)。

## 3. 用 N 条轨迹说明“到底把什么放进一组”

固定任务 $x$ 和初始环境条件，采样 $N$ 条轨迹：

$$
\tau_i=\bigl(s_1^{(i)},a_1^{(i)},r_1^{(i)},s_2^{(i)},\ldots,s_{T_i+1}^{(i)}\bigr).
$$

这里 $i$ 是轨迹编号，$t$ 是环境交互步，$T_i$ 是该轨迹长度；在本节的分组公式中，$s_t^{(i)}$ 专指**实现中用于匹配的状态表示**。一轮 action 对应一段 response，不等于一个 token。

GiGPO 的基本步骤组为：

$$
\mathcal G_x(s)=\{(i,t):s_t^{(i)}=s\}.
$$

这表示：在当前任务的全部 rollout 中，找到从观察 $s$ 发出动作的那些**步骤实例**，把它们组成一组。组内保留每次出现的数据，不把相同动作文本去重。相似度版本则用指定匹配规则代替精确相等。

例如下面两行可以分到同组：

| 数据行 | 所属轨迹／时间 | 当前观察 | 采取的动作 | 该实例的后续回报 |
|---|---|---|---|---:|
| 1 | 轨迹 1，第 2 步 | 冰箱关着 | 打开冰箱 | 1 |
| 2 | 轨迹 2，第 5 步 | 冰箱关着 | 去台面 | 0 |

如果只减组均值，两行局部优势分别是 $+0.5$、$-0.5$。这是人为构造的解释例子，只展示局部分量，不包含 episode advantage。

由此可见：时间步可以不同，前面历史可以不同，action 可以相同或不同；比较组由**动作发生前的匹配状态**决定。若同一轨迹重复访问这个观察，其多次出现也可以参加分组。

## 4. GiGPO、HGPO、GraphGPO 共享前提，但共享信息的方式不同

### 4.1 GiGPO：在共同观察处比较各次实际后续回报

$$
G_t^{(i)}=\sum_{u=t}^{T_i}\gamma^{u-t}r_u^{(i)},\qquad
A_{i,t}^{\mathrm{step}}=
\frac{G_t^{(i)}-\operatorname{mean}_{(j,u)\in\mathcal G_x(s_t^{(i)})}G_u^{(j)}}
{\operatorname{std}_{(j,u)\in\mathcal G_x(s_t^{(i)})}G_u^{(j)}+\varepsilon}.
$$

$G_t^{(i)}$ 是这一次动作之后，该轨迹实际得到的折扣回报；不是额外提供的正确步骤标签。公式展示除标准差版本，代码还支持只减均值。GiGPO 将此局部优势与整轨迹优势组合。

**相同观察让比较组可以建立，但比较分数仍然受各自后续动作影响。** 同一动作在两条轨迹里，也可能因为后来一成一败而得到不同的局部信用。

### 4.2 HGPO：共同观察还不够，要逐层匹配历史

用当前观察及最近 $k$ 个历史观察组成后缀：

$$
C_k(i,t)=(s_{\max(1,t-k)}^{(i)},\ldots,s_t^{(i)}),\qquad
\mathcal G_k(i,t)=\{(j,u):C_k(j,u)=C_k(i,t)\}.
$$

所有比较仍限定在同一个任务组内。$k=0$ 只比较当前观察，$k=1$ 要求前一个观察也相同，以此类推。越严格的组越小：

$$
\mathcal G_0(i,t)\supseteq\mathcal G_1(i,t)\supseteq\cdots\supseteq\mathcal G_K(i,t).
$$

HGPO 分别计算各层优势再加权。它没有取消相同 state 前提，而是增加历史匹配条件。论文公式和当前代码使用的是**观察状态序列**；不能自动说它精确匹配了历史动作、推理文字等完整 prompt 字段。

### 4.3 GraphGPO：共同状态既是分组锚点，也是跨轨迹连接点

GraphGPO 把相同 state 合并为图节点，把实际采样的 $(s,a,s')$ 作为边。**节点是 state，action 是边上的信息，不是必须将整个 $(s,a)$ 匹配为相同才允许比较。**

例如两条已采轨迹包含：

```text
轨迹 1：S → U → F       失败
轨迹 2：S → V → U → G   成功
```

共享的 $U$ 节点允许图把轨迹 2 的 `U → G` 信息用于评价轨迹 1 的 `S → U`。随后，它按同一出发状态的出边分组，对图评分做相对比较。

所以 GraphGPO 的区别有两层：**同状态用于合并图节点；同起点用于比较动作。** 它不是只把 GiGPO 的分组容器改成了 graph，而是用图中的成功距离替换各实例的实际后续回报作为局部评分。更完整推导见 [GraphGPO 分析](./ICML2026-GraphGPO/analysis.md)。

## 5. “没有重复状态”与“有重复但没有回报差异”是两回事

| 条件 | 局部组内比较会发生什么 |
|---|---|
| 某个观察只出现一次 | 组大小为 1，无法比较；GiGPO 中心化为零，HGPO 跳过单例层 |
| 同一观察出现多次，但比较分数全部一样 | 中心化后局部优势为零；加 $\varepsilon$ 不能创造差异 |
| 同一观察出现多次，比较分数有差异 | 可以形成非零相对优势；但不自动证明它是准确的因果贡献 |
| 观察字符串相同，隐藏状态或相关历史不同 | 形式上可分组，统计上可能混合不同决策条件 |

这里说的是**用于比较的分数**，不只看终局成功标签。即使终局奖励一样，折扣、剩余长度或其他奖励不同，也可能使 return-to-go 不同；只有组内实际评分相等时，才可直接断言该局部分量为零。

“没有重复状态就不能运行算法”也过强：

- 同任务 rollout 通常共享初始条件，最初的比较组仍可能存在；困难在于后面是否还有可复用锚点。
- GiGPO、GraphGPO 通常保留整轨迹优势；某步局部优势为零，不代表它的总优势为零。
- **HGPO 主公式没有固定加整轨迹项，本地代码默认 `base_group=False`。** 若所有可用层都退化，该步的 HGPO 优势可以为零；可选加入轨迹项是另外的配置。
- 没有可重用的内部连接时，GraphGPO 仍能建图，但“通过其他轨迹的成功后缀重评某步”的收益会减少。全失败且没有成功通路时，图也不能凭空找到未知成功路径。

## 6. ProGPO：要区分“状态可比较”和“跨轨迹状态重复”

论文的 progress 定义为轨迹内首次访问观察的比例：

$$
\mathcal V_{i,t}=\{o_1^{(i)},\ldots,o_t^{(i)}\},\qquad
\delta_{i,t}=\mathbf 1\{o_{t+1}^{(i)}\notin\mathcal V_{i,t}\},\qquad
P_i=\frac1{T_i}\sum_{t=1}^{T_i}\delta_{i,t}.
$$

$o_t^{(i)}$ 是环境观察。$\mathcal V_{i,t}$ 只记录**第 $i$ 条轨迹自己的历史**。它需要判断“这条观察在我自己的轨迹里见过没有”，并不要求“别的轨迹也来到这里”。

例如同题两条轨迹全失败：

```text
轨迹 1：S → A → B → C，首次访问标记 1,1,1，P₁ = 1
轨迹 2：S → D → D → D，首次访问标记 1,0,0，P₂ = 1/3
```

除初始状态 $S$ 外，没有跨轨迹的共同中间观察，轨迹级 ProGPO 仍能比较 $P_1$ 和 $P_2$。这里只能说第一条覆盖更多新观察，不能据此断言它一定离任务成功更近。

对于全失败且 progress 存在差异的任务组，轨迹级替代优势为：

$$
A_i^{\mathrm{progress}}=\lambda\frac{P_i-\overline P}{\sigma_P+\varepsilon}.
$$

它比较的是同任务轨迹的 progress。**若接在 GiGPO／HGPO 上，比较集合改为基础方法已有的状态组／历史组，相应匹配前提继续存在。** 单例组即使有 progress，也不能通过组内中心化产生相对差异。

还要区分论文和当前代码：本地 ProGPO 的 C2 分支对“前后观察发生变化”计分，回到早先见过的观察也可能得分；论文则要求轨迹内首次访问。两者对 `A → B → A` 的评分不同。详见 [代码对照第 5 节](./02-状态分组与信用分配-文字公式代码对照.md)。

## 7. 同目录其他方法为什么不能全部归为同状态重分组

**CRBC** 同样识别共享锚点，但核心操作是合并经验转移、保留频率并求 Bellman 不动点。它用 $Q(s,a)-V(s)$ 形成局部信用，而不只是换一组均值和标准差。其局部项还明确要求该状态观察到至少两个不同的语义动作。[CRBC 分析](./arXiv2026-CRBC/analysis.md)

**ProCredit** 在每轮后运行任务检查，计算进度差作为奖励。不同轨迹不必到达同一个中间状态，只要各自状态上的检查结果可计算，就能产生逐轮信号。它和 ProGPO 都使用 progress 一词，但一个来自任务检查，一个来自观察覆盖，含义不同。[ProCredit 分析](./arXiv2026-ProCredit/analysis.md)

**SCA** 从同一截图和指令直接采样多个动作，组的共同起点由采样设置保证。它利用点击坐标、命中奖励或目标位置调整信用，不是在长轨迹中回溯寻找共同节点。[SCA 分析](./arXiv2026-SCA/analysis.md)

目录外的 **GRPO** 按同任务的完整回答／轨迹分组，**Dr.MAS** 关注多 agent 的角色统计；也不能仅因它们都使用相对优势，就认为必须跨轨迹匹配相同中间环境状态。见 [已有时间线对照](../01-GRPO到GraphGPO与DrMAS-时间线与分组优势对比.md)。

## 8. 用实验环境理解这些方法的适用条件

| 方法 | 已核对的任务范围 | 与本问题的关系 |
|---|---|---|
| GiGPO | ALFWorld、WebShop；搜索 QA | 环境／检索器提供观察；搜索扩展还使用相似度分组 |
| HGPO | ALFWorld、WebShop | 当前观察和近期观察历史可记录、匹配 |
| GraphGPO、CRBC | ALFWorld、WebShop、Sokoban | 记录观察之间的实际转移，再进行图式信息共享 |
| ProGPO | ALFWorld、WebShop | 可计算观察覆盖；具体比较组取决于基础算法 |
| ProCredit | AppWorld、ToolSandbox | 需要可运行的中间进度检查 |
| SCA | GUI grounding、离线动作预测 | 输入包含截图，动作具有可利用的空间坐标 |

详细训练／评测划分见 [数据集总表](../07-逐篇论文的数据集与任务分类总表.md)。**用相同环境不代表用了相同的分组算法；用了外部环境，也不保证观察相等就能公平共享全部后续信息。**

## 9. 为什么纯文本数学推理更难直接照搬

纯文本数学推理可以定义状态和动作。若状态是完整前缀、动作是下一个 token 或下一段推理，则：

$$
s_t=(x,a_1,\ldots,a_{t-1}),\qquad s_{t+1}=s_t\oplus a_t.
$$

$\oplus$ 表示追加文本。在固定 token 序列表示下，两条前缀一旦分叉，继续追加 token 不会让完整前缀重新相同。共同题目和共同前缀仍可形成组，但普通独立采样没有保证后续大量重复前缀。

两种说法必须区分：

1. **“完整推理前缀相同”**：容易精确判断，但跨轨迹重复可能稀少。
2. **“数学含义上处于相同求解状态”**：可能存在，但需要定义和抽取当前约束、已知结论、变量条件、子目标等信息。

例如两条推理都得到 `2x = 4`，可以尝试把这个方程当作共同状态。但在复杂题里，仅匹配某一行公式可能忽略假设或尚未解决的条件。数学状态抽象的可靠性是新增问题，不能当作现成的环境接口。

此外，若把不断增长的完整推理前缀当作 ProGPO 的观察，通常每次追加都得到一个“从未见过”的前缀，导致 $P_i\approx1$，同样难以提供区分。**即使 ProGPO 不需要跨轨迹共同状态，其观察覆盖定义也不能机械搬到自然语言推理前缀上。**

工具辅助数学、定理证明器等设置可以有外部执行或证明状态，需要另行定义匹配规则；上述讨论限定于普通纯文本解题。

## 10. 分组影响 advantage，不改变每条样本的概率比定义

令 $p_{i,t}$ 是该步真实 prompt，$y_{i,t,\ell}$ 是 response 的第 $\ell$ 个 token。更新时仍计算：

$$
\rho_{i,t,\ell}=\frac{\pi_\theta(y_{i,t,\ell}\mid p_{i,t},y_{i,t,<\ell})}
{\pi_{\theta_{\mathrm{old}}}(y_{i,t,\ell}\mid p_{i,t},y_{i,t,<\ell})}.
$$

分子、分母针对**同一个样本、同一个真实上下文**。重新分组改变的是该样本乘上的优势，不会把另一个轨迹的 prompt 代进分母。状态是否可比，影响局部信用的统计含义，不是概率比能否定义的条件。

这份笔记的研究判断是：要把这条路线迁移到纯文本数学推理，首先需要回答“用什么表示认定两个中间位置可比较”，再讨论如何在该组内计算优势。把文本切成步骤、找到可靠共同状态、构造有差异的评分，是三个不同的问题。
