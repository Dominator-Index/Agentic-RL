# DyJR 解读：用近期成功轨迹的概率约束，缓解 GRPO 的多样性坍缩

> 论文：**DyJR: Preserving Diversity in Reinforcement Learning with Verifiable Rewards via Dynamic Jensen-Shannon Replay**。阅读版本：arXiv:2603.16157v1，14 页；核对日期：2026-10-08。
>
> [本地 PDF](./DyJR.pdf) · [论文页面](https://arxiv.org/abs/2603.16157v1)。当前核对的[作者主页](https://bimu.wang/)仍标注 Under Review；未找到可确认的官方实现。本笔记依据全文、算法和附录，以下补充数学推导明确与论文原文区分，不声称做了源码复现。

## 1. 这篇文章到底在解决什么问题

**DyJR 在 GRPO 上增加一个历史成功轨迹的概率正则项，希望模型提高正确率的同时，不要过早遗忘其他可行的生成方式。**

它与 CoSo 都关心探索与多样性，但着力点不同：CoSo 为不同 token 分配熵奖励；DyJR 用近期历史策略在成功轨迹上的概率作为参照，约束当前策略的变化。

它仍采用我们熟悉的 RLVR 设置：同一道题采样多条完整输出，用最终答案／程序执行结果给奖励。它没有要求跨轨迹找到相同中间 state，也没有把 trajectory advantage 重新拆成 step-level advantage。

| 问题 | DyJR 的设置 |
|---|---|
| 基础优化算法 | GRPO；实验主基线不带原有 KL 项 |
| 每个问题采样多少条 | $G=8$ |
| 奖励 | 可验证的二值奖励 $R(x,y)\in\{0,1\}$ |
| 额外保存什么 | 近期正确轨迹、生成时选中 token 的 log-probability、时间信息 |
| 保存失败轨迹吗 | 本文 replay buffer 只接收 $R=1$ 的轨迹 |
| 新增训练信号 | 历史轨迹上的 JS 风格概率正则 |
| 需要 critic 或 frozen LLM assessor 吗 | 方法没有新增这两类模块 |

## 2. Motivation：正确答案反复训练，为什么可能损害探索

作者观察到，GRPO 在训练早期会迅速变得确定：输出分布的熵下降，最高概率 token 的概率上升。模型可能更稳定地产生少数答案路径，却失去尝试其他路径的能力。

历史 rollout 又很昂贵，因此已有方法尝试 replay：保存成功轨迹，把它们作为额外样本继续进行策略更新。论文批评的风险是，如果不断推动这些成功输出的概率上升，会进一步集中概率质量。

需要区分两件事：

- **历史输出是正确的**，说明它值得参考。
- **历史输出的概率应不断增大**，并不由正确性自动推出。

DyJR 提议保留历史概率尺度，而非只保留答案文本。例如，过去某个成功轨迹 token 的概率是 $0.2$，当前已变成 $0.8$，继续对它做正向模仿会进一步增大概率；概率正则则会对这种过大偏离施加约束。

这是一种机制解释，不是“所有 replay 都会坍缩”的定理。历史数据是否多样、更新权重、样本选择和基础算法都会影响结果；本文实验支持的是其具体设置下的改进。

## 3. 原有 GRPO 的部分保持了什么

对问题 $x$，当前采样策略 $\pi_{\mathrm{old}}$ 生成 $G$ 条输出：

$$
y^{(1)},\ldots,y^{(G)}\sim\pi_{\mathrm{old}}(\cdot\mid x),
\qquad
A_i=\frac{R(x,y^{(i)})-\mu_x}{\sigma_x+\epsilon_{\mathrm{num}}}.
$$

$\mu_x,\sigma_x$ 是这组回报的均值和标准差。$\epsilon_{\mathrm{num}}$ 是常见的数值稳定项，为教学补入，论文 Eq. (1) 未显式写出。

对第 $i$ 条输出的第 $j$ 个 token，常见的 token 级 GRPO 写法为：

$$
\rho_{i,j}(\theta)=
\frac{\pi_\theta(y_j^{(i)}\mid x,y_{<j}^{(i)})}
{\pi_{\mathrm{old}}(y_j^{(i)}\mid x,y_{<j}^{(i)})}.
$$

策略损失对这些位置的 clipped surrogate 聚合：

$$
\mathcal L_{\mathrm{GRPO}}
=-\operatorname{Avg}_{i,j}
\left[
\min\left(\rho_{i,j}A_i,
\operatorname{clip}(\rho_{i,j},1-\epsilon_\ell,1+\epsilon_h)A_i\right)
\right].
$$

论文 Eq. (2) 使用序列级简写，附录配置写明 `token-mean`。上式用于说明 token 级训练关系，不冒充未公开代码的逐行实现。

**DyJR 不改组内 $A_i$ 的定义。** 它在这个在线损失之外，再增加一项来自 replay 的正则。

## 4. 动态 buffer 如何构造

### 4.1 保存近期正确轨迹及其旧概率

对历史轨迹 $b$，保存：

$$
\left(x_b,y_b,\{\ell^{\mathrm{hist}}_{b,j}\}_{j=1}^{L_b},k_b\right),
\qquad
\ell^{\mathrm{hist}}_{b,j}
=\log\pi_{\theta_{k_b}}(y_{b,j}\mid x_b,y_{b,<j}).
$$

$k_b$ 是生成时的训练步，$L_b$ 是轨迹 token 数。这些 log-probability 是历史数值，后续作为固定参照，不需要保留每个历史模型权重。

在训练步 $t$，论文的保留条件是：

$$
R(x_b,y_b)=1,\qquad t-k_b\le M.
$$

超过最大年龄 $M$ 的样本被移除，默认 $M=8$。因此这里的“保留早期多样性”不是把训练最初的轨迹永久留到最后，而是通过短期、连续传递的参照影响训练路径。

### 4.2 按同题正确数，从高到低接收样本

对每个问题计算：

$$
C_x=\sum_{i=1}^{G}\mathbf 1\{R(x,y^{(i)})=1\}.
$$

这就是当前 $G$ 条 rollout 中有几条成功。算法按 $C_x=G,G-1,\ldots,1$ 的顺序，接收对应问题的正确轨迹，直到达到当步的目标接收量。

所以它**优先接收高正确率问题的成功样本**，不是优先挑 hardest case。作者称这能在成功样本稀缺时逐步放宽标准；但若容易问题已经填满配额，困难问题并不保证获得覆盖。这个规则也没有直接按语义差异挑选轨迹。

### 4.3 训练早期多收，后期少收

默认前 20 步保留当步 rollout 的目标比例为 20%，之后降为 5%。比例描述的是目标接收量；因为只收正确样本，成功样本不足时可能无法填满。

在固定年龄窗口下，每步接收量降低，buffer 会随着旧样本退出而缩小。它是预先设置的时间阶段调度，不是算法实时检测熵后自动决定何时切换。

论文的常规阶段估算为：512 个问题 × 每题 8 条 = 4096 条新 rollout，$4096\times5\%\times8\approx1638$ 条历史序列。实际边界计数和取整依实现而定。

## 5. 数学核心：回放样本上究竟计算什么

### 5.1 当前概率与生成时概率的比值

对 replay 中的轨迹 $b$，用当前模型在原问题与原前缀上重新计算：

$$
\ell^\theta_{b,j}
=\log\pi_\theta(y_{b,j}\mid x_b,y_{b,<j}),
\qquad
u_{b,j}=\exp(\ell^\theta_{b,j}-\ell^{\mathrm{hist}}_{b,j}).
$$

同一个 token、同一个前缀，比较两个时间点的概率。$u>1$ 表示当前概率增加，$u<1$ 表示下降。

这不是把不同问题、不同 state 的概率直接比较。也不是对历史文本重新自由生成答案：计算当前 log-probability 时使用原轨迹前缀进行 teacher forcing。

保存的是已生成 token 的 log-probability，不是整个词表 logits。当前模型仍需做前向和反向传播；省掉的是重新加载／前向历史模型来计算分母。

### 5.2 论文实际采用的惩罚函数

论文 Eq. (8) 定义：

$$
f(u)=u\log u-(u+1)\log\frac{u+1}{2}.
$$

再对 replay batch 的每条序列、每个 token 求平均：

$$
\mathcal L_{\mathrm{JS}}(\theta)
=\frac{1}{|\mathcal B_{\mathrm{replay}}|}
\sum_{b\in\mathcal B_{\mathrm{replay}}}
\frac{1}{L_b}\sum_{j=1}^{L_b}f(u_{b,j}).
$$

这忠实对应 Eq. (9) 的先逐序列长度平均、再对序列平均。附录同时给出通用 `token-mean` 配置，两者在变长 batch 上不等价，复现时需确认具体哪个损失使用哪个聚合方式。

最终损失是：

$$
\boxed{
\mathcal L_{\mathrm{total}}
=\mathcal L_{\mathrm{GRPO}}
+\alpha_{\mathrm{JS}}\mathcal L_{\mathrm{JS}}
}.
$$

默认 $\alpha_{\mathrm{JS}}=0.05$。GRPO 提供任务改进方向，历史正则对概率偏移施加约束。

### 5.3 为什么它不同于对成功答案做 SFT

以下为根据论文公式补充的导数分析。固定历史 log-probability，记 $z=\log\pi_\theta(y_j\mid x,y_{<j})$，则：

$$
f'(u)=\log\frac{2u}{u+1},
\qquad
\frac{\partial f(u)}{\partial z}
=u\log\frac{2u}{u+1}.
$$

最小化该项时，在把单个 log-probability 当作局部变量的解释下：

| 当前／历史概率比 | 正则的局部作用 |
|---|---|
| $u<1$ | 倾向于提高该 token 当前概率 |
| $u=1$ | 该项梯度为零 |
| $u>1$ | 倾向于降低该 token 当前概率 |

例如，历史概率为 $0.2$，当前变为 $0.05$，正则倾向于拉回；当前变为 $0.8$，正则也会抑制过大的增幅。实际参数更新还受到 softmax 耦合及其他损失影响，不能解释成独立直接修改一个概率。

对比 SFT 的 $-\log\pi_\theta(y_j\mid x,y_{<j})$，它对这个 log-probability 的导数恒为 $-1$，会持续推动示范 token 概率增大。**DyJR 的参照是历史概率，而不只是“这个 token 属于正确答案”。**

因此，摘要中的“用分布约束替代直接梯度更新”不能理解为 replay 不产生梯度。它仍产生梯度，只是使用正则损失，而不是额外的奖励优势 surrogate 或直接模仿损失。

### 5.4 JS 公式需要严格区分的细节

对两个归一化分布 $p,q$，标准 JS 为：

$$
\operatorname{JS}(p,q)
=\frac12\operatorname{KL}(p\Vert m)
+\frac12\operatorname{KL}(q\Vert m),
\qquad m=\frac{p+q}{2}.
$$

若 $q$ 覆盖 $p$ 的支持，对 $u=p/q$ 代入上述 $f$，可直接推导：

$$
\mathbb E_{v\sim q}f\left(\frac{p(v)}{q(v)}\right)
=2\operatorname{JS}(p,q).
$$

所以论文 Eq. (8) 相对其 Eq. (4) 的标准 JS 定义差一个系数 2。这个常数可以吸收到正则系数中，但复现时应保留论文的 $f$，不能混用系数。

更实质的限制是：**实际 buffer 经正确性、问题正确数和年龄筛选，采样分布并不是未经筛选的历史策略分布。** 每条样本的分母也是其生成模型的 token 概率，不是显式计算的所有历史策略混合分布概率。

因此，Eq. (9) 更谨慎的表述是：在筛选后的 replay token 上计算 JS 风格的概率比惩罚。仅凭这些公式，不能宣称它是当前完整序列分布与历史混合分布之间严格无偏的 JS 估计；逐 token 正则也不自动等于序列级 JS。

此外，标准 JS 的期望值有上界，不代表每个 $f(u)$ 样本项都有同样上界。$u$ 很大时该样本项可继续增大。“有界 JS”不能直接充当实际所有 batch 损失／梯度有界的证明。

## 6. 完整算法如何运行

按论文 Algorithm 1，可还原为：

1. 用当前采样策略对每个问题生成 $G=8$ 条输出，计算最终奖励和组内优势。
2. 清理超过最大年龄的 replay 样本。
3. 按问题正确数从高到低，选择部分正确输出入库，保存文本、生成时 log-probability 和时间信息。
4. 在新 rollout 上计算 GRPO 损失。
5. 从 replay buffer 均匀采样，在这些旧问题及旧前缀上计算当前模型概率。
6. 计算 $u$、$f(u)$ 和 replay 正则，与 GRPO 损失相加更新策略。

新样本在这一步既可能参与在线训练，也可能进入 buffer 后被 replay；论文算法先入库再采样，没有要求必须隔一个训练步才能回放。

**当前问题的 rollout 全失败时，DyJR 没有为这些失败轨迹新增细粒度奖励。** 它仍可从其他问题或之前成功的 buffer 样本获得正则信号；若始终没有成功样本，这个正样本 replay 机制就缺少可用参照。空 buffer 的具体处理没有公开代码可核对，不能擅自归为某个已实现分支。

## 7. 为什么可能有效，以及真实贡献在哪

机制可以分为三个部分：

- **用概率参照抑制单向强化。** 对已有成功轨迹，并非概率越高越好；过度提高和过度遗忘都会受到相应约束。
- **用近期数据减轻陈旧参照的阻碍。** 模型能力不断变化，太旧的样本概率可能不适合当前阶段。最大年龄限制控制这种偏离。
- **在训练早期增加参照覆盖。** 早期是概率分布快速集中的阶段，多保留一些成功轨迹有机会避免过早丢失可行模式。

真正的贡献是这三个设计的组合：**近期成功样本的选择、分阶段接收调度，以及基于缓存 log-probability 的分布正则。** JS 散度、经验回放或动态 buffer 本身都不是本文首次提出。

论文没有给出完整的多样性保持／RL 收敛定理；附录主要是实验设置和早期接收率消融。保持更多探索路径是由机制与实验支持的解释，不是对任意任务的保证。

### 8.2 数学结果：Mean@256 不等于 Pass@256

Table 1 的平均分如下：

| 方法 | 数学六项平均分 |
|---|---:|
| GRPO | 29.8 |
| DAPO | 30.8 |
| RLEP | 31.7 |
| Ex-GRPO | 32.8 |
| DPH-RL | 31.3 |
| DyJR | **34.1** |

DyJR 相比 GRPO 提升 **4.3 个百分点**。表中除 Minerva 使用 Mean@16 外，其余使用 Mean@256：每题在温度 0.7 下采样多次，计算平均正确率。**不是“256 次里至少对一次”的 Pass@256，也不是 greedy Pass@1。**

GRPO 和 DyJR 报告三次独立运行的均值与标准差；其他方法未在该表同样报告误差，因此“显著优于所有方法”不应未经统计检验进一步加强。

### 8.3 SQL 结果与例外

| 方法 | BIRD Pass@1 | BIRD Pass@16 | Spider Pass@1 | Spider Pass@16 |

### 8.4 消融验证了哪些设计

| 消融 | 平均分 | 可支持的观察 |
|---|---:|---|
| 默认 JS | 34.1 | 主设置 |
| 换为 Forward KL | 32.5 | 在此设置下 JS 版本更好 |
| $\alpha=0.01$／$0.2$ | 32.7／30.9 | 约束过弱或过强都不理想 |

这些结果说明早期 replay 的安排影响最终效果。但减少早期数据同时改变了数据量与有效正则信号，因此不能只凭该消融就严格证明收益全部来自多样性，而与准确率监督或优化强度无关。

### 8.5 它确实分析了 learning dynamics

论文 Figure 1–2 跟踪训练过程中的熵，以及平均 rank-1、rank-2、rank-3 token 概率。rank 指同一个上下文下，词表概率从大到小的排序，不是轨迹名次。

作者观察到，GRPO 较快形成高 rank-1 概率；DyJR 相对保留更多 rank-2／rank-3 概率质量。Figure 3 还报告 Beyond AIME 的 Pass@k，采样预算最高到 1024。

这些是分布集中程度与多次采样效益的证据，**不直接等于语义上不同解法的数量**。此外，Eq. (11) 的熵指标对 top-k 概率重新归一化，是截断近似熵，不能与完整词表熵不加区分地比较。

## 9. 与 GRPO、GiGPO、Dr.MAS、CoSo 的关系

| 方法 | 主要变化 | 是否重构 advantage | 是否使用历史轨迹 |
|---|---|---|---|
| GRPO | 同题 rollout 组内回报归一化 | 基础组相对优势 | 基础流程不依赖长期 buffer |
| GiGPO | 跨轨迹重复状态提供更细的动作参照 | 是 | 核心分组不要求跨训练步的 replay |
| Dr.MAS | 多角色输出的奖励统计与归一化 | 调整角色对应的优势统计 | 核心不依赖本文这种 replay |
| CoSo | 按 token 对动作预测的影响加权熵 | 核心不改 advantage | 历史概率参照不是其核心 |
| DyJR | 在 GRPO 外加入近期成功轨迹的概率正则 | **不改原组优势** | **是** |

DyJR 的正则按 token 计算，但这不使它成为 token-level credit assignment：它没有估计哪个推理步骤导致成功，只是在这些历史上下文上约束策略概率变化。

## 10. 局限、复现疑点与适用边界

1. **只利用已经出现过的成功。** 无成功数据时不能凭空构造正确路径；也不解决全失败组中的过程归因。
2. **多样性取决于 buffer 本身。** 高正确数优先可能偏向容易题和主流模式，未提供语义去重或少数模式覆盖保证。
3. **经验正则与精确 JS 要区分。** 成功筛选、不同历史模型、token 级聚合影响估计含义，详见 §5.4。
4. **恢复已消失模式的能力有限。** 由导数可知 $u\to0$ 时 $u\log(2u/(u+1))\to0$；历史 token 概率已极小时，这个直接恢复信号可能很弱。避免早期丢失可能比事后恢复更重要，这是公式推导得到的解释。
5. **效率有实验条件。** 缓存旧概率节省历史模型计算，但 replay 仍需当前模型前后向；论文比较的是具体配置下的每 token 延迟，不能推出任意 replay 比例都没有成本。
6. **部分配置表述不完全一致。** Table 3／附录将 `Replay Bsz=512` 描述为每次融合新增项，§5.4 又按每次 replay 训练样本数解释；该 512 与 $4096\times5\%$ 也不是同一数量。复现应分别明确入库数、buffer 容量与抽样训练数。
7. **没有独立反向 KL 对照。** 论文以采样来源不匹配等理由排除它；这不等于 reverse KL 在数学上完全不能用重要性采样等方式估计，只能说明本文没有验证该替代设计。

## 11. 完整故事线与对我们研究的启发

DyJR 的完整逻辑是：GRPO 学习过程中可能过早集中到少数输出；成功轨迹值得复用，但反复提高其概率也可能加剧集中；因此保存近期成功轨迹及其生成时概率，用 JS 风格正则限制过度偏离，并在早期增加参照覆盖。

对我们之前讨论的方案，它提供了一个不同的切入点：**细粒度训练改进不一定要重构 advantage，也可以设计更合适的概率变化约束。** 但 DyJR 没有做“全失败时启用 assessor”，也没有识别成功轨迹内部哪些 turn／token 真正贡献了奖励。

如果继续研究，值得检验的一个具体问题是：当前 replay 对成功轨迹的所有 token 都施加历史概率约束，是否会同时保留冗余或错误中间推理？怎样只保留有助于未来探索的部分，而不是完整冻结过去的生成习惯？这是由本文局限推导出的研究问题，尚不能仅凭此声称已有新颖算法。
